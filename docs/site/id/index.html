Meja Kerja Seluler HeLa MCP

Rangkaian distribusi 10 server Model Context Protocol (MCP) yang dapat direproduksi untuk agen AI. Menghadirkan orkestrasi dual-backbone (penalaran + grafik memori), transport stdio deterministik, dan konfigurasi klien per-profil di 8 harness agen kecerdasan buatan.

Tentang Ekosistem Ini

Sepuluh server khusus, masing-masing bertindak layaknya sel biologis dengan satu tugas utama. Dua backbone mengoordinasikannya: HeLa Mitosis (penalaran dan perutean tugas) dan HeLa Genome (grafik pengetahuan memori persisten). Delapan sel lainnya melengkapi kapabilitas berkas, eksekusi shell, proses PTY, riset data, browser web, desain UI, kontrol mobile Android, dan pemodelan 3D.

Katalog lengkap perkakas, entrypoint, dan repositori: 04 Arsitektur. Dinamai sebagai penghormatan kepada Henrietta Lacks (1920–1951): spesialisasi modular, replikasi deterministik, dan daya tahan jangka panjang.

Instalasi

Gunakan Node.js 22 LTS untuk full stack yang diuji dan Git 2.30+. Genome memakai binding SQLite Node; CLI SQLite bersifat opsional. Alur kerja browser, Android, dan Blender memerlukan runtime/perangkat masing-masing.

SHELL // KLONING_DAN_INSTAL
git clone https://github.com/Hela-Ecosystem/hela-mcp-ecosystem.git
cd hela-mcp-ecosystem
./setup.sh --profile dev-workspace --client opencode --mode runtime
AGENT // PROMPT_INSTALASI_OTOMATIS
Please autonomously install the HeLa Cellular MCP Ecosystem through one profile-aware hela-runtime MCP endpoint:

1. Environment & Harness Detection:
   Verify Node.js (>= 22.x LTS), Git (>= 2.30.0), and build tools. Identify current client (Cursor, Claude, OpenCode, Antigravity, Zed, Codex).

2. Tanyakan profil yang paling sesuai kepada pengguna sebelum instalasi:
   - Tampilkan katalog ringkas: https://hela.my.id/profiles.html
   - Untuk penjelasan persona, workflow, keanggotaan server, dan prasyarat, tampilkan: https://hela.my.id/library/docs/profiles.html
   - Tawarkan: minimal (riset/memori ringan), dev-workspace (pengembangan/browser/desain lengkap), headless-server (core headless), research, web-devops, android-testing, 3d-modeling, atau all.
   - Tunggu pilihan pengguna dan simpan sebagai <confirmed_profile>. Jika tidak memilih, gunakan minimal. Jangan menjalankan setup sebelum profil dikonfirmasi.

3. Clone & Install the Managed Runtime:
   git clone https://github.com/Hela-Ecosystem/hela-mcp-ecosystem.git
   cd hela-mcp-ecosystem && chmod +x setup.sh update.sh
   ./setup.sh --profile <confirmed_profile> --client <detected_client> --mode runtime --non-interactive
   ./setup.sh doctor --profile <confirmed_profile> --mode runtime
   Safely merge generated client configuration into my active MCP configuration file.
   Do not deploy each hela-* cell as a separate client server.

4. Synchronize Companion Skills:
   Link or copy ecosystem companion skills matching <confirmed_profile> from project-mcp/skills, designer-mcp/skills, browser-mcp/skill, and chaining-mcp/skills into ~/.agents/skills/.

5. Load the Runtime Profile Context:
   - Do not create or copy a static persona prompt into the workspace.
   - After connecting, read the hela://profile/context resource or request the hela-profile-bootstrap MCP prompt.
   - Treat the selected runtime profile as the authority for active organelles and available tools.

6. Final Handshake:
   Initialize the workspace memory graph through the exposed Genome tool when that organelle is active, and confirm the selected profile and runtime tools.

setup.sh memasang sumber terkunci di prefix privat ${XDG_DATA_HOME:-$HOME/.local/share}/hela/installations/, memverifikasi respons MCP nyata, lalu membuat fragmen konfigurasi klien untuk ditinjau dan digabungkan manual. Repositori dan pengaturan klien aktif tidak ditimpa. Flag penting: --prefix, --snapshot, --reconfigure (fragmen baru), dan --without-model (tanpa aset Needle opsional).

Delapan profil mendukung --mode individual|runtime|docker|docker-runtime|nix. Docker membutuhkan daemon aktif dan Compose v2; build native membutuhkan Python, make, dan compiler C/C++, atau toolchain Nix terkunci. Lihat panduan instalasi untuk persyaratan, Compose, GC root Nix, dan pemulihan kegagalan.

Mode runtime mendukung --transport http --port 8080. Listener hanya di loopback dan harus dijalankan secara eksplisit; gunakan doctor --url http://127.0.0.1:8080/mcp untuk memeriksa endpoint aktif. Engine browser, kunci provider, bridge Android/Blender, dan autentikasi GUI tetap kebutuhan terpisah.

Alternatif satu endpoint: tambahkan --runtime pada profil pilihan. Runtime bukan profil tersendiri. Discovery tidak menjalankan sel; panggilan pertama hanya menjalankan sel tujuannya. Jika profil tidak dipilih, runtime dan installer memakai minimal; profil lain tetap bisa dipilih secara eksplisit.

Verifikasi

Tiga gerbang verifikasi, semuanya diharapkan berstatus hijau sebelum digunakan:

SHELL // GERBANG_VERIFIKASI
./setup.sh doctor --profile dev-workspace
npm run test:install  # Regresi installer, bukan pengujian hardware
npm run test:matrix   # 80 kombinasi profil × klien
HASIL YANG DIHARAPKAN
Doctor memeriksa sel pada profil terpilih, bukan mewajibkan sepuluh server. Tambahkan --runtime jika runtime dipasang untuk memeriksa kecocokan katalog tanpa startup sel. Konfigurasi, sesi GUI terautentikasi, provider eksternal, dan perangkat keras adalah pemeriksaan terpisah. Lihat 08 Diagnostik.

Langkah Selanjutnya

  1. Pahami organismenya. Pelajari 04 Arsitektur untuk memahami model dual-backbone dan katalog alat per server.
  2. Pilih profil deployment. Delapan profil siap pakai (dari workstation desktop lengkap hingga CI headless) di 06 Profil & Konfigurasi — buat file konfigurasi klien menggunakan workbench interaktif.
  3. Jalankan alur kerja. Enam pipeline lintas-MCP (rekayasa fitur, riset, verifikasi UI, QA mobile, orkestrasi PTY, 3D) di 05 Alur Kerja.
