SPEC_02 // Hela-Ecosystem-MCPDOSSIER: DUAL_BACKBONE_TOPOLOGY

Architecture

Two backbones coordinate ten cells: Mitosis plans and routes; Genome keeps durable memory. Other cells own their domain state, including browser and terminal sessions. Connect separately over stdio or through the optional runtime.

The dual backbone

TABLE 2.1 — BACKBONE RESPONSIBILITIES
BackboneOwnsNever owns
Mitosis (hela-mitosis)Step-by-step reasoning, task decomposition, tool-chain routing, prompt templatesPersistent state
Genome (hela-genome)SQLite knowledge graph, entities/relations, session context, central syncExecution decisions

Interaction rule: agents reason through Mitosis, persist through Genome, act through the remaining cells. Verified synergies (see npm test): Mitosis+Genome (backbone), Enzyme+Cytosol (research), Membrane+Nucleus+Ribosome (workspace).

Transport

Standalone clients spawn cells over MCP stdio using the canonical inventory paths. The optional runtime also supports Streamable HTTP. Transport choice does not prevent tools from using the network or changing host resources. Endpoint authentication and authorization remain deferred; process separation is not an OS sandbox.

Server reference

Ten cells. Scope CORE runs headless; SPECIALIZED needs GUI, device, or runtime extras.

HeLa Runtime

hela-runtime · hela-runtime · OPTIONAL · profile-scoped tools

Optional runtime 1.2.1: exposes generated, revision/build/config-validated schemas without starting cells. A first tool call starts only its target; concurrent calls share startup. If no profile is selected, the runtime uses minimal; broader profiles remain explicit choices. Timeout recovery reaps the old process before restarting; namespacing remains opt-in. Node 22 Nix packages build on x86_64-linux and aarch64-linux.
