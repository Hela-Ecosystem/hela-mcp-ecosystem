Diagnostics

Start with doctor for the selected profile. Configuration, MCP discovery, external services, authenticated clients, and hardware are separate checks.

Doctor report anatomy

SHELL // DOCTOR_SECTIONS
node setup.mjs doctor --profile dev-workspace
# If using the runtime: verify cold catalog parity too
node setup.mjs doctor --profile dev-workspace --runtime
# Tested full-stack environment: Node 22 LTS

For a managed installation, pass the same --mode and profile, or node setup.mjs doctor --prefix /path/to/prefix --json. On native Windows, run the matching doctor command through setup.ps1 or setup.cmd. Doctor verifies source/build identity and actual MCP replies; runtime modes also verify private HTTP discovery. Use --url http://127.0.0.1:8080/mcp to check an explicitly started listener. A health response alone is not MCP readiness.

Scenarios & fixes

Entrypoint missing

Symptom: missing or changed build, or an incomplete-install marker. Re-run setup with the same prefix, mode, and profile: it installs locked dependencies, rebuilds, and probes MCP. Dirty sources, origin mismatches, and unmanaged directories are refused; preserve your changes rather than resetting them. See the installation guide. Do not remove a lock belonging to an active installer.

Handshake failure

Symptom: entrypoint present but JSON-RPC fails. Check node --version in the client environment; use Node 22 LTS for the tested full stack. Native bindings can require matching build tools and ABI. Use the selected project's reproducible environment, run npm ci, and rebuild only that cell.

Google quota / OpenRouter errors

Check credentials, quota, network, and the configured model/provider. Enzyme supports keyless network fallbacks; those can also fail. Mitosis local execution depends on its engine/model, and generative tools can fail when no provider is configured. Successful discovery does not establish provider readiness.

Matrix failure after editing inventory

Check the failing assertion: JSON validity, canonical profile membership, repository directory/entrypoint, environment shape, and Codex mcp_servers sections. Re-run npm run test:matrix. After changing version/revision metadata or builds, regenerate and validate the selected schema catalog and documentation.

Client sees no tools

Check absolute paths, the client's Node PATH, enabled servers, and the selected profile. Review configuration before deliberately reloading only the affected client; some clients auto-reload on save. Preserve unrelated definitions and live synchronization hooks.

Runtime catalog and client ownership

A missing or stale catalog must not trigger eager startup. After a cell build, run npm run catalog:generate -- --profile dev-workspace, then runtime doctor. Cold discovery should start zero cells. Runtime is a serve mode (--runtime), not a profile.

Zed can forward a server already owned by Codex, producing duplicate warnings. Do not remove shared top-level definitions to silence them. Authenticated ACP verification is separate; see the version-specific client guidance.

Before database or vault changes, take validated backups. Never restore over active SQLite files or force a conflict winner. Documentation publication needs no runtime restart.

STILL STUCK
Open an issue at Hela-Ecosystem/hela-mcp-ecosystem with reviewed/redacted doctor output and the failing gate. Never attach private client configuration, credentials, or raw environments.
