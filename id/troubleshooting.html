Diagnostik

Jalankan setup.sh doctor terlebih dahulu — diagnostik akan mengklasifikasikan penyebab kegagalan secara otomatis. Skenario di bawah ini mencakup seluruh permasalahan yang ditandai oleh doctor.

Anatomi laporan doctor

SHELL // BAGIAN_DOKTOR
./setup.sh doctor --profile dev-workspace
# Jika menggunakan runtime: periksa katalog tanpa startup sel
./setup.sh doctor --profile dev-workspace --runtime
# Environment full-stack yang diuji: Node 22 LTS

Untuk instalasi terkelola, gunakan mode dan profil yang sama, atau ./setup.sh doctor --prefix /path/to/prefix --json. Doctor memeriksa identitas sumber/build dan respons MCP nyata; mode runtime juga memeriksa discovery HTTP privat. Gunakan --url http://127.0.0.1:8080/mcp untuk listener yang dijalankan secara eksplisit. Respons health saja bukan bukti kesiapan MCP.

Skenario kegagalan & perbaikan

Entrypoint tidak ditemukan

Gejala: build hilang/berubah atau ada penanda instalasi belum selesai. Jalankan ulang setup dengan prefix, mode, dan profil yang sama untuk memasang dependensi terkunci, membangun, dan menguji MCP. Sumber kotor, origin berbeda, dan direktori tidak terkelola ditolak; simpan perubahan Anda, jangan reset. Lihat panduan instalasi. Jangan hapus lock milik installer yang masih aktif.

Kegagalan handshake JSON-RPC

Gejala: entrypoint tersedia tetapi JSON-RPC gagal. Periksa node --version pada environment klien; gunakan Node 22 LTS untuk full stack yang diuji. Native binding memerlukan toolchain dan ABI yang sesuai. Gunakan environment proyek, jalankan npm ci, lalu bangun ulang hanya sel terkait.

Kuota Google / Galat OpenRouter

Periksa kredensial, kuota, jaringan, dan model/provider terkonfigurasi. Enzyme mendukung fallback jaringan tanpa kunci, tetapi fallback juga dapat gagal. Eksekusi lokal Mitosis bergantung pada engine/model; alat generatif dapat gagal tanpa provider. Keberhasilan discovery bukan bukti kesiapan provider.

Kegagalan matriks setelah mengedit inventaris

Periksa assertion yang gagal: validitas JSON, anggota profil, direktori/entrypoint, format environment, dan bagian mcp_servers Codex. Jalankan ulang npm run test:matrix. Setelah metadata versi/revisi atau build berubah, buat ulang dan validasi katalog skema serta dokumentasi.

Klien tidak melihat perkakas

Periksa path absolut, PATH Node milik klien, server aktif, dan profil terpilih. Tinjau konfigurasi sebelum sengaja memuat ulang hanya klien terkait; sebagian klien otomatis reload saat disimpan. Pertahankan definisi lain dan hook sinkronisasi aktif.

Katalog runtime dan kepemilikan klien

Katalog hilang atau usang tidak boleh memicu startup semua sel. Setelah build, jalankan npm run catalog:generate -- --profile dev-workspace, lalu doctor runtime. Discovery dingin harus menjalankan nol sel. Runtime adalah mode penyajian (--runtime), bukan profil.

Zed dapat meneruskan server yang sudah dimiliki Codex sehingga muncul peringatan duplikat. Jangan hapus definisi bersama hanya untuk membungkamnya. Verifikasi ACP terautentikasi tetap terpisah; lihat panduan khusus versi klien.

Sebelum mengubah database atau vault, buat cadangan tervalidasi. Jangan menimpa SQLite aktif atau memaksakan pemenang konflik. Publikasi dokumentasi tidak membutuhkan restart runtime.

MASIH MENGALAMI KENDALA?
Buka isu pada Hela-Ecosystem/hela-mcp-ecosystem dengan output doctor yang sudah ditinjau/disensor dan pemeriksaan yang gagal. Jangan lampirkan konfigurasi privat, kredensial, atau environment mentah.
